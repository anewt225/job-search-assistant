# Rewrite Playbook

Diagnosis without drafting is homework. This file turns rubric scores and harvested vocabulary into copy the user can paste.

## Rules that apply to everything below

1. **Never invent experience.** Rewrites reframe and translate what exists. If a claim isn't substantiated by the résumé, notes, or the user's own words, ask — don't fill the gap.
2. **Write in first person.** LinkedIn is not a résumé; third-person profiles read as institutional.
3. **Give options, not verdicts. 3-5 named alternatives for EVERY section.** Users pick voice far better than they generate it, and the variants surface the tradeoff. **Name each alternative by its theme or by the cause it addresses** - never "Option A/B/C". A named variant tells the user what they are choosing; a lettered one makes them re-derive it. See "Naming the alternatives" below.
4. **Show the character count** against the live cap on every draft.
5. **Preserve their voice.** Mirror the user's own phrasing from their notes and CMF wherever possible. A rewrite that sounds like a consultant wrote it will not get published — the profile that actually ships beats the better profile that doesn't.
6. **Flag every stretch claim** so the user can veto before it goes live.
7. **Run the Newport filter before delivering.** Strike every sentence that *asserts* passion, drive,
   or mission; keep every sentence that *demonstrates* capability. If a draft loses more than a third
   of its length, the draft was mostly assertion - rewrite from the proof.
8. **Voice-match against real samples.** If the user supplied writing samples, posts, or a prior
   About section, mirror sentence length, contraction use, and vocabulary register. If they supplied
   none, say so explicitly: *"drafted without voice samples - expect this to need a personality pass."*

## Naming the alternatives

Each variant is named for the reader it serves or the problem it solves, so the choice is legible:

**For a headline:**
| Name | Optimizes for | Trade |
|---|---|---|
| **Discoverability-Max** | The algorithm and the 70-char mobile window | Reads flatter |
| **The Intersection** | The differentiating combination only this person owns | Weaker on raw search |
| **Career-Changer Bridge** | Making the switch legible (Graham) | Spends characters on framing |
| **Credential-Forward** | Risk-averse, credential-driven readers | Can read as conservative |
| **Plain-Language** | The human click; problem solved, stated simply | Weakest for search |

**For an About billboard**, name by opening move: *The Problem I Solve* - *The Unlikely
Combination* - *The Proof-First Open* - *The Direct Ask* - *The Operator's Lens*.

**For a section flagged by a specific criterion**, name by cause: e.g. if B4 scored low, the variants
are *Translated for the Target*, *Scope-Forward*, *Systems Framing* - each naming the diagnosis it
answers.

**When multiple target titles are in play**, generate one variant per title so the user can see how
the same truth reads aimed at each - this is the most useful variant axis when the target is still
being narrowed.

## Current character limits

| Field | Limit | Visible before cutoff |
|---|---:|---|
| Headline | 220 | ~70 in mobile search results |
| About | 2,600 | ~300 desktop / ~200 mobile |
| Experience description | 2,000 | ~250 |
| Custom URL slug | 3–100 | — |
| Skills | 50 max | Top 3 pinned |

*Published guidance in the source books is out of date on these — several cite a 120-character headline and a 2,000-character About. Use the values above and say so if the user cites otherwise.*

## Headline

Confirm posture first (see the contested criterion in `profile-rubric.md`): **Aspirational** or **Objective**. If the user has no preference, default to the synthesis — the most target-adjacent title they can claim truthfully, no "aspiring."

Draft 3-5, named per the table above. The archetypes:

- **Discoverability-Max.** Target title first, then the two highest-frequency JD terms. Prioritizes the algorithm and the mobile-search 70-character window.
- **The Intersection.** Title plus the differentiating intersection — what this person has that peers don't.
- **Plain-Language.** Title plus a plain-language statement of the problem they solve. Weakest for search, strongest for the click.

Common pattern, from peer profiles:
`[Target Title] | [Domain/Industry] | [Differentiator or Credential]`

Check every variant:
- Target title appears verbatim as a recruiter would type it
- Meaning survives truncation at 70 characters
- No invented titles, no "Ninja/Guru/Rockstar"
- Under 220 characters
- A human being could say it out loud without embarrassment

## About

Seven blocks. The first two matter more than the other five combined.

### 1. Billboard — first ~300 characters
State the problem the person solves, in their voice, containing the target title. This is the entire section for most readers.

Failure modes to avoid: opening with personality traits; opening with "I'm a passionate..."; opening with career chronology; burying the target role in paragraph three.

Draft 3-5 named variants. Test each by reading *only* the first two lines and asking: *do I know what this person does and want to read more?*

### 2. Hook / bridge — 2–3 sentences
Compress the career path into a trailer, not the movie. Especially load-bearing for career-changers, where the bridge *is* the pitch.

### 3. Intersection payoff — 1–2 sentences
The line a referrer could read aloud to introduce this person. Names the specific combination they own. If the user has a T-shape (deep in one domain, broad across another), this is where it gets stated plainly.

### 4. Proof points — 3
One each, ideally: depth, breadth, and the intersection. Every one carries a Number, a Name, or a Notable. 1–2 sentences each — resist the urge to explain.

### 5. Specialties line
Comma-separated, drawn from the 🔴 and 🟡 buckets. This is the one place a list is appropriate. Keep it to ~15 terms; past that it reads as stuffing and now degrades semantic match quality.

### 6. Personality — ONE line
One specific, surprising, human detail. Specific beats comprehensive: a named hobby with an outcome beats three abstract adjectives. This line generates more interview small-talk than anything else on the profile.

### 7. Call to action
What they're looking for, where, and how to reach them — including an email address, so a recruiter without InMail credits can still make contact. Recruiters need the ask stated; they will not infer it.

Assemble, count characters, trim to 2,600. **Trim proof points before trimming the billboard.**

## Experience bullets

The formula: **Keyword + Impact**. The algorithm wants the first, the recruiter wants the second, and a bullet with only one of them fails half its audience.

For each role, 3–5 bullets. More is not better — LinkedIn rewards relevance, and a long list dilutes the strong bullets.

Per bullet:
1. Start from the résumé bullet if one exists — do not draft from scratch.
2. Substitute harvested target vocabulary for internal jargon, preserving the truth.
3. Ensure at least one of the 3 Ns.
4. Add the denominator. "Reduced processing time 40%" is fine; "Reduced processing time 40% for a $14B program serving 10M+ beneficiaries" is the version that survives comparison.
5. Cut hedges: *helped, assisted, supported, was responsible for, participated in.*

**Prior roles get translated, not deleted.** For career-changers, earlier experience is often the differentiator once it's framed in target vocabulary — the operations job that reads as unrelated history in its original phrasing frequently reads as directly relevant once renamed. Ask "what did this actually teach that the target role needs?" before writing.

## Skills

- Pull the top 20 most frequent terms from the harvested JDs.
- Pin the 3 a recruiter would filter on first.
- Remove skills irrelevant to the target — they dilute, and they date the profile.
- Include acronym and expansion where both appear in the wild.

---

## Recommendations

Draft the *request*, not the recommendation. Each request should: open with genuine specific gratitude, name the 2–3 attributes to emphasize, refresh the recommender's memory with a concrete shared project, and keep it under ~500 characters.

Prioritize: recent > old, manager > peer, in-domain > out-of-domain. Two strong recent recommendations beat six stale ones.

---

## Output format

For every section, produce a three-column comparison:

| Section | Current | Proposed | Why |
|---|---|---|---|

The **Why** column is not decoration — it cites the criterion and the points recovered (e.g. "B1 billboard: 1 → 3, +3.5 pts"). It's what lets the user judge the change rather than accept it on faith, and what makes the tool teachable rather than magic.

End with the stretch-claim list for explicit approval before anything is published.
